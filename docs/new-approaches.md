## 1. BaCO — байесовская оптимизация для автотюнинга компиляторов
- Источник: Hellsten et al., arXiv:2212.11142 (ASPLOS 2024). https://arxiv.org/abs/2212.11142
- **Факт:** BO, специализированная под автотюнинг: перестановочные, порядковые и непрерывные параметры, известные и неизвестные ограничения; на TACO/RISE/HPVM2FPGA в среднем 1.36–1.56× быстрее код при малом бюджете.
- **Интерпретация:** пространство space.rs — ровно «перестановка + порядковые факторы + бит vectorize/unroll». Новый режим `search --strategy bo` в crates/coffee-ten-bench/src (новый bo.rs), random не трогаем. Простой GP/TPE с перестановочным ядром (Kendall/Hamming) пишется руками на std.
- Сложность: 3–4 PR (кодирование расписания → суррогат → acquisition → сравнительный прогон).
- Риски: бит-в-бит не затронут (меняется только выбор кандидатов); зависимость — нет, если без внешних крейтов линейной алгебры (GP на ≤ сотнях точек — ручной Cholesky); протокол — новый режим, тот же бюджет замеров.
- Научная ценность: высокая — «BO vs random vs model-top-10 vs local при равном бюджете» на одной оси.

## 2. Эволюционный поиск + learned cost model (Ansor/MetaSchedule)
- Источник: Shao et al., MetaSchedule, arXiv:2205.13603 (NeurIPS 2022). https://arxiv.org/abs/2205.13603
- **Факт:** пространство задаётся вероятностной программой из стохастических решений; поиск — обучаемый (learning-driven) фреймворк поверх пространства; покрывает пространства SOTA-фреймворков.
- **Интерпретация:** два куска: (а) переписать space.rs как набор «sample-инструкций» (split factor, reorder, vectorize) — даст расширяемость (k-split, другие регистровые тайлы, которых сейчас нет); (б) режим `--strategy evo` — мутации = уже существующие `neighbors`, отбор по model.rs. Без обучаемой модели — честно «эволюция с аналитической моделью».
- Сложность: evo — 2 PR; переписывание space — 3+ PR (**ЧЕРНОВИК**).
- Риски: бит-в-бит — новые формы расписаний (k-split) меняют порядок сложений по k ⇒ нужен тест на эталон, k-split только с сохранением возрастающего порядка; зависимостей нет.
- Ценность: средняя-высокая (local vs evo — разные стратегии исследования).

## 3. Hyperband / successive halving для бюджета замеров
- Источник: Li et al., arXiv:1603.06560 (JMLR 2018). https://arxiv.org/abs/1603.06560
- **Факт:** ускоряет random search через адаптивное распределение ресурса и раннюю остановку; задача как bandit; >10× ускорение vs BO на ряде задач.
- **Интерпретация:** ресурс = число раундов замера. Режим: 1000 случайных кандидатов × 3 раунда → лучшая треть × 9 → … → финал 30 раундов как сейчас. Код: run.rs/search.rs, новый halving.rs; финальное сравнение — по старому протоколу (30 interleaved rounds).
- Сложность: 2 PR. Риски: бит-в-бит нет; протокол — ранние раунды короче, это отдельный режим, а финальные числа — по старому протоколу; без «ок» Никиты в основной протокол не вносим (ранний стоп ранее был в «не берём»!).
- Ценность: высокая для вопроса «сколько замеров реально нужно», прямо дополняет гипотезу A.

## 4. Аналитический выбор тайлов (BLIS: «analytical modeling is enough»)
- Источник: Low, Igual, Smith, Quintana-Ortí, ACM TOMS 42(2), 2016. https://doi.org/10.1145/2925987
- **Факт (аннотация):** параметры GEMM в слоистой схеме BLIS можно определить аналитически из параметров памяти, без эмпирического автотюнинга.
- **Интерпретация:** режим `--strategy analytic`: вычислить ri×rj по числу векторных регистров/латентности FMA и тайлы по L1/L2 из `bench/peak`, ноль поиска. Это «нулевой бюджет»-бейзлайн для гипотезы A: если он близок к model-top-10, ценность поиска мала. Код: новый analytic.rs рядом с model.rs; MAX_ACCUMULATORS уже есть в space.rs.
- Сложность: 1–2 PR. Риски: нет; зависимостей нет; параметры кэша M5 нужны с Мака.
- Ценность: высокая — новое сравнение «формула vs поиск».

## 5. Transfer / кросс-железо cost models (TLP, Tenset)
- Источник: Zhai et al., TLP, arXiv:2211.03578 (ASPLOS 2023). https://arxiv.org/abs/2211.03578
- **Факт:** признаки извлекаются из примитивов расписания, а не из ручных аппаратных признаков; модель с одной платформы плохо переносится на другую («cross-hardware unavailability»), предложен MTL-TLP.
- **Интерпретация:** в coffee-ten обучение модели запрещено правилом «без фиттинга», поэтому — только как *анализ*: признаки = шаги `Schedule` (у нас уже текст Loop IR); проверить, переносится ли ранжирование model.rs с Linux CI на M5 (Spearman между машинами). Нейросеть не берём.
- Сложность: 1–2 PR (экспорт признаков + скрипт сравнения). Риски: Python-зависимости в bench/ только опционально; протокол не затронут.
- Ценность: средняя — «переносима ли аналитическая модель между CPU» как отдельная гипотеза.

## 6. Ансамбль стратегий с бандитом (OpenTuner)
- Источник: Ansel et al., OpenTuner, PACT 2014. https://doi.org/10.1145/2628071.2628092 [мета]
- **Факт [мета]:** фреймворк автотюнинга, где несколько техник поиска работают одновременно, а бюджет между ними распределяет многорукий бандит (AUC credit assignment).
- **Интерпретация:** когда есть random/local/evo/bo, режим `--strategy ensemble` распределяет замеры между ними. Только после п.1–3.
- Сложность: 2 PR. Риски: нет бит-в-бит; сравнивать честно трудно (стохастика) ⇒ много seed'ов.
- Ценность: средняя.

## 7. Методология сравнения стратегий автотюнинга
- Источник: Schoonhoven et al., arXiv:2210.01465. https://arxiv.org/abs/2210.01465
- **Факт:** сравнивают алгоритмы оптимизации для автотюнинга GPU-ядер при ограниченном бюджете времени; пространство дискретное и невыпуклое.
- **Интерпретация:** взять их постановку: кривая «лучший найденный vs число замеров», усреднённая по многим seed'ам, вместо одной точки ratio. Можно делать на *кэшированных* замерах (замерить всё пространство один раз на Маке → стратегии гонять офлайн по таблице). Код: новый `bench/strategy_curves.py` + `search --replay results.jsonl`.
- Сложность: 2 PR. Риски: нет; один полный замер пространства на Маке.
- Ценность: очень высокая — устраняет главный слабый пункт (4 прогона, по одному seed).

## 8. Смещение измерений и рандомизация раскладки (Mytkowicz; Stabilizer)
- Источники: Mytkowicz et al., ASPLOS 2009, https://doi.org/10.1145/1508244.1508275 [мета];
  Curtsinger & Berger, STABILIZER, ASPLOS 2013, https://doi.org/10.1145/2451116.2451141 [мета].
- **Факт [мета]:** (Mytkowicz) «безобидные» изменения среды — размер переменных окружения, порядок линковки — дают систематическое смещение, сравнимое с эффектом оптимизаций; (Stabilizer) многократная случайная перераскладка кода/стека/кучи во время выполнения делает время ≈нормальным и позволяет статистически корректно сравнивать.
- **Интерпретация:** Stabilizer — LLVM-плагин, тянуть нельзя. Дешёвый аналог без зависимостей: в run.rs рандомизировать (по seed) размер env-паддинга и смещение выравнивания буферов A/B/C, и порядок линковки/имён функций в сгенерированном C; гипотеза: ранжирование расписаний устойчиво к раскладке. Код: run.rs, codegen-c/compile.rs (смещение буферов — только в харнессе, ядро не меняется).
- Сложность: 2 PR. Риски: бит-в-бит не затронут (данные те же); протокол меняется ⇒ отдельный режим `--layout-random`, «ок» Никиты; на macOS ASLR уже есть.
- Ценность: высокая — проверка угроз валидности (раздел Validity).

## 9. Статистика замеров: доверительные интервалы и многоуровневые повторы
- Источники: Kalibera & Jones, ISMM 2013, https://doi.org/10.1145/2464157.2464160 [мета];
  Georges et al., OOPSLA 2007, https://doi.org/10.1145/1297027.1297033 [мета];
  Hoefler & Belli, SC15, https://doi.org/10.1145/2807591.2807644 [мета].
- **Факт [мета]:** (Kalibera–Jones) повторы на нескольких уровнях (сборка/процесс/итерация), число повторов на уровне выбирается по оценке вариации; эффект — отношение с доверительным интервалом. (Georges) сравнение по одной точке приводит к неверным выводам, нужны CI. (Hoefler–Belli) 12 правил отчётности, в т.ч. непараметрические CI медианы.
- **Интерпретация:** в stats.rs добавить bootstrap/непараметрический CI медианы и CI для ratio гипотезы A (сейчас ratio — точка), и уровень «процесс» (перезапуск бинаря) в run.rs. Без зависимостей (bootstrap на собственном RNG из stats.rs).
- Сложность: 2 PR. Риски: нет; протокол — добавляется только отчётность; уровень «процесс» — режим.
- Ценность: высокая; дёшево.

## 10. Фьюзия эпилога (XLA fusion)
- Источник: Snider & Liang, arXiv:2301.13062. https://arxiv.org/abs/2301.13062
- **Факт:** разбор проходов фьюзии в XLA по исходникам; реализованные стратегии фьюзии дали до 10.56× на их примере.
- **Интерпретация:** README прямо пишет «no epilogue fusion yet». Предложение: в coffee-ten-loop разрешить неидеальный nest «matmul → relu/bias» (элементная операция после полного k), в lower.rs и codegen-c; `exp` исключить (libm). Бит в бит сохраняется, если эпилог применяется к окончательному `C[i,j]` после всех k.
- Сложность: 3–4 PR (**ЧЕРНОВИК**, меняет Loop IR — «перфектные гнёзда»). Риски: Loop IR/парсер/модель (model.rs моделирует только nest 1); новых зависимостей нет.
- Ценность: средняя-высокая (новый класс ядер для модели).

## 11. Equality saturation над графом (egg / TENSAT)
- Источники: Willsey et al., egg, POPL 2021, https://doi.org/10.1145/3434304 (arXiv:2004.03082);
  Yang et al., TENSAT, arXiv:2101.01332 (MLSys 2021).
- **Факт:** egg — e-graphs с rebuilding и e-class analyses; TENSAT применяет все переписывания сразу (equality saturation) вместо последовательной эвристики и находит лучшие графы.
- **Интерпретация:** в coffee-ten-ir почти нечего переписывать (+,−,*,/,relu,max,exp,matmul,reduce). Законны только переписывания, не меняющие float-результат (напр. `x*1`, удаление дубликатов CSE); ассоциативность/дистрибутивность ломают бит-в-бит. egg — новая зависимость. Вывод: **не рекомендую сейчас**; максимум — ручной CSE без egg (1 PR).
- Ценность: низкая для текущего IR.
