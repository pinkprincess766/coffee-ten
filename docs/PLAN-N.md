План N0–N3. Согласовано 3 ноября 2026 в группе
«Наука» приложения Grok Bot: Вера дала N0–N3 и подтвердила уточнения Codex;

## Рабочий процесс

- Вера (агент Grok) ведёт план и готовит самодостаточные ТЗ в этом файле.
- Codex (ChatGPT на Маке Никиты) реализует задачи, проверяет результат,
  открывает отдельные PR и выполняет согласованные измерения на Маке.
- Ника (агент Grok) принимает PR по диффу и CI. Слияние — после ревью и
  успешного CI, без force. Спорные изменения передаются Никите.
- В группу возвращается короткий пакет ссылок на PR с указанием проверок.
  Уточнения отправляются одним сообщением; ответы не дублируются агентами.
- Во время активной работы Codex проверяет группу через computer use.
  Постоянное фоновое наблюдение или автоматический запуск не настроены.

Уточнение Никиты от 4 ноября 2026: Codex продолжает работу самостоятельно,
без Grok Bot. Обращения к группе и ожидание ответов агентов прекращены;
согласованные технические ограничения сохраняются.

## Общие ограничения

- Один PR — одна правка; новых зависимостей нет.
- Порядок сложений сохраняется; численные результаты сверяются с эталоном
  бит в бит там, где это предусмотрено текущим контрактом проекта.
- Случайный поиск остаётся базовой линией с прежним поведением.
- Подгонка аналитической модели под замеры запрещена. Для будущего GP нужно
  отдельное согласованное ТЗ; из этого пакета оно не следует.
- Hyperband, рандомизация раскладки памяти, один прогрев на 300 мс и C9
  требуют явного решения Никиты и этим документом не разрешены.

## N1 — сырые раунды в JSONL

Что сделать:

- Сохранять `round_index`, сырые GFLOP/s, `elapsed_ns` и `iterations`.
- Сохранять порядок раундов.
- `drift` остаётся общим флагом прогона. Отдельный флаг drift для каждого
  раунда не вводится.
- Агрегаты остаются в прежних полях.

Затрагиваемые части: bench writer, документация схемы JSONL (C16), тест схемы.
Конкретные имена файлов определяются по актуальному коду перед реализацией.

Критерии готовности:

- Тест пересчитывает медиану из того же массива сырых `rates` и проверяет
  побитовое совпадение с записанным агрегатом.
- Старые логи прогонов 1–4 по-прежнему читаются.

Статус: реализовано в PR N1; проверки и ревью указаны в PR.

## N2 — протокол и бюджет

Зависит от N1.

Что сделать:

- В метаданных фиксировать CPU, размер задачи, хэш пространства расписаний,
  хэш исходников и флаги clang.
- Суммарное время измерений и время компиляции записывать раздельно.
- В `docs/protocol.md` описать сравнение новых стратегий по суммарному времени
  измерений, с отдельным учётом компиляции.
- Существующий `--budget` случайного поиска продолжает считать кандидатов;
  его смысл и поведение не изменяются.

Критерий готовности: поля описаны в схеме; тест проверяет их присутствие.

Статус: реализовано в PR N2; проверки и ревью указаны в PR.

## N3 — `--replay`

Зависит от ключа метаданных N2 и данных N1.

Что сделать:

- Стратегия поиска читает готовую полную таблицу измерений вместо живых
  замеров.
- Таблица привязана к ключу N2; несовпадение ключа приводит к ошибке.

Критерии готовности:

- С фиксированным seed случайный поиск в replay выбирает тех же кандидатов,
  что и при живом прогоне на той же таблице.
- Регрессионный тест работает на небольшом игрушечном пространстве в CI.
- Полное пространство на Маке измеряется только после слияния N1–N3.

Статус: реализовано в PR N3; проверки и ревью указаны в PR.

## N4–N20

Формат: цель и что меняется, тест/приёмка, ограничения. Общие ограничения выше действуют для всех пунктов. Запрещено во всех пунктах: новые зависимости, изменение порядка сложений, отбор кандидатов моделью, ранняя остановка, подгонка аналитической модели. Случайный поиск остаётся базовой линией.

### N4 — bootstrap для медианы и отношения медиан

Зависит от: N1.

- Что: Доверительные интервалы для медианы GFLOP/s кандидата и для отношения медиан двух прогонов. Resampling связанных раундов (одинаковый `round_index` ресэмплится парой). Фиксированный seed, свой PRNG без новых крейтов.
- Приёмка: на синтетических раундах интервал детерминирован при seed; при одинаковых данных отношение = 1 входит в интервал.
- Ограничения: только анализ логов; на выбор кандидатов не влияет.

Статус: статистический API реализован в PR N4; интеграция с отчётами остаётся N11/N12.

### N5 — тайлы в стиле BLIS из `sysctl`

Зависит от: —.

- Что: Читать `hw.l1dcachesize`, `hw.l2cachesize`, `hw.cachelinesize` (macOS); вывести кандидатные размеры тайлов и добавить их как значения (не фильтр) только в новое пространство `--space v2`; без флага пространство прежнее.
- Приёмка: юнит-тест формулы на фиксированных размерах кэшей; без `sysctl` (Linux CI) — fallback на прежние значения; тест: хэш пространства по умолчанию не изменился.
- Ограничения: opt-in: `--space v2` — новое пространство с новым хэшем и новым ключом N2. Без флага старое пространство и базовая линия (прогоны 1–4) воспроизводятся бит в бит: тот же хэш, та же выборка случайного поиска при том же seed. Кандидаты моделью не отбрасываются.

Статус: реализовано в PR N5; параметры, формула и границы совместимости — `docs/cache-tiles.md`.

### N6 — порядок циклов в reduce

Зависит от: —.

- Что: По ревью #114: в сгенерированном C цикл по `r` самый внутренний и читает со страйдом. Добавить вариант с `r` снаружи по отношению к непрерывной оси — только в `--space v2` (вместе с N5).
- Приёмка: результат совпадает с эталоном бит в бит: порядок сложений по `r` для каждого выходного элемента не меняется (тест на несколько форм); тест: хэш и выборка пространства по умолчанию при том же seed не изменились.
- Ограничения: перестановка допустима только если для каждой ячейки результата сложения идут в том же порядке; opt-in как в N5, без флага пространство прежнее.

Статус: ТЗ готово; реализация не начата.

Зависит от: —.

### N8 — EMI-фаззинг: сохраняющие преобразования

Зависит от: N7.

- Приёмка: для каждого преобразования — тест бит в бит; список преобразований с обоснованием в `docs/fuzzing.md`.
- Ограничения: любое преобразование, меняющее порядок сложений, запрещено.
